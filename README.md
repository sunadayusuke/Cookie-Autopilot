# Cookie Autopilot

Cookie の同意画面を、一度決めた方針どおりに自動で処理する Chrome 拡張です（Manifest V3。Arc など Chromium 系ブラウザでも動作します）。同意画面を見つけたら断るボタンを自動で押し、見つからなければ同意画面を非表示にします。画面にはできるだけ見せません。UI はすべて日本語です。

## インストール

### Chrome ウェブストアから

[Chrome ウェブストア](https://chromewebstore.google.com/detail/PLACEHOLDER)からインストールできます（公開後に URL を差し替えます）。

### 開発者向け: ソースから読み込む

1. 依存関係のインストールとビルド

   ```sh
   pnpm install
   pnpm build
   ```

   `dist/` に拡張一式が生成されます。

2. Chrome で `chrome://extensions` を開く
3. 右上の「デベロッパーモード」を有効にする
4. 「パッケージ化されていない拡張機能を読み込む」から `dist/` フォルダを選択する

以降コードを変更したときは `pnpm build`（または監視ビルドの `pnpm dev`）を実行し、`chrome://extensions` の拡張カードにある再読み込みボタンを押してください。popup / options はページを開き直すだけで最新の内容になります。

## 使い方

### 最初の設定（初期設定ページ）

拡張機能を読み込むと、自動で「初期設定」のタブが開きます（拡張の更新時は、まだ初期設定を終えていない場合に一度だけ開きます）。あとから開き直すときは、popup の「詳細設定 →」から options ページを開き、「その他」の「はじめの設定をもう一度見る」を押してください。

1. **どこまで許可しますか？** — 3 つの設定から 1 つを選びます。既定は「ほどよく守る」です。
   - **しっかり守る**: 必要なもの以外はすべて断ります。いちばん安心ですが、サイトによっては表示の設定が次回に引き継がれません
   - **ほどよく守る（おすすめ）**: サイトを快適に使うための「設定の記憶」だけ許可し、分析や広告は断ります
   - **ゆるく守る**: サイト運営者のアクセス解析とおすすめ表示も許可します。追跡型の広告と用途不明のものは断ります
   - 3 つのカードの下には、もう一段強い **すべて拒否** を小さく置いています。断るボタンがあれば断り、「OK」しかない画面では**何も押さずに**画面を消します（許可するものは「しっかり守る」と同じです）。サイトに答えを返さないぶん、**同じ同意画面が何度も出たり、サイトによっては一部の機能が使えないことがあります**
   - 追跡型の広告と用途が不明なものは、どの設定でも断ります
2. **それぞれの Cookie は何をするの？** — 「必要なもの」「設定の記憶」「アクセス解析」など 7 種類の Cookie が何のためのものかを、開いて読める説明とあわせて確認できます。各設定でどれが許可されるかも一目でわかります
3. **この設定で始める** ボタンを押すと保存され、あとは Cookie の同意画面が出るサイトを開くだけです

サイトによっては「必要なものだけ許可」のような選択画面ではなく、「同意する／同意しない」の 2 択しか無いことがあります。その場合はどの設定を選んでいても、必要なもの以外はすべて断ります（細かく選べるサイトでだけ、選んだ設定どおりに選びます）。

### ツールバーの popup

拡張アイコンをクリックすると、いま開いているタブについての設定と状態を表示します。

- **最初の設定がまだの場合**は「設定する」ボタンが表示され、押すと初期設定ページが開きます
- **状態表示**: サイト名の下に、そのページで拡張が動いたかどうかを短く表示します（「✓ 処理しました」「見つかりませんでした」「同意画面なし」「無効」「確認中」「同意画面なし」）。詳しい内容は下の「このサイトでの結果」に出ます
- **このサイトでの結果**: 何が起きたかを詳しく表示します。サイトの選択画面でカテゴリごとに選んだ場合は、実際に「許可したもの」と「断ったもの」がタグで並びます。断るボタンや教えたボタンを押した場合は、そのボタンに書かれていた文言をそのまま添えて表示します。同意画面を閉じただけのとき（サイト側に細かい選択肢が無く、拒否とも言い切れない操作だったとき）は「サイトの同意画面を閉じました。」とだけ表示します。処理できなかったときは、その理由に合わせて「断るボタンが見つかりませんでした。」「同意画面は見つかりましたが、押せるボタンを判別できませんでした。」「設定画面を開きましたが、項目を判別できませんでした。」「ボタンを押しましたが、同意画面が閉じませんでした。」のいずれかを表示し、あわせて下の『断るボタンを教える』で登録できる旨のヒントも出ます。一度答えたサイトは次回以降 Cookie の同意画面自体が出ませんが、その場合も「◯月◯日にこのサイトの同意画面に答えたので、今回は出ていません。」のように以前の記録を表示します（バッジも「✓ 対応済み」になります）。この記録は options の「その他」からまとめて消せます
- **このサイトの設定**: 行全体がボタンになっていて、押すと詳細に切り替わります。詳細では Cookie の種類ごとに ON・OFF を切り替えられ（「必要なもの」は常に許可）、いま開いているサイトだけの設定として即座に保存されます。「このサイトでは動かさない」を ON にすると、そのサイトでは何もしません。「全体の設定に戻す」を押すとサイトごとの設定を消して全体の設定に従います。行の右側には現在の状態（全体の設定と同じ／このサイトだけ調整中／動かさない）が出ます
- **断るボタンを教える**: 自動処理がうまくいかないサイト向けに、押してほしい「断る」ボタンを直接指定できます。押すと画面右上に案内トーストが出るので、対象のボタンをクリックしてください（Esc で中止すると自動処理を再開します）。選んだボタンはその場でクリックされ、次回以降そのサイトを開いたときも同じボタンを直接クリックします。ただし購入・決済・削除・ログイン・送信のような**取り返しのつかない操作に見えるボタンは登録できません**（「このボタンは登録できません」と表示され、別のボタンを選び直せます）。同じく、**文字の入っていないアイコンボタン**（`aria-label` も `title` も無いもの）も登録できません。登録したボタンは次回以降も文言と照合してから押すため、文言が無いと二度と押せなくなるからです
- **このページで再実行**: 開いているページに対して検出・処理をもう一度やり直します（SPA で同意画面が後から出た場合などに使います）。設定は押したときに読み直すので、直前に「このサイトの設定」を変えた場合もその設定で動きます（「このサイトでは動かさない」に変えたときは何もせず終わります）。押したあとは結果が届くまで「確認中」と表示されます（ボタンを教えるモードの最中に押した場合は、選択の邪魔をしないよう無視されます）
- **詳細設定**: options ページを新しいタブで開きます

`chrome://` ・`edge://` ・`about:` ・拡張ページ（`chrome-extension://`）では「このページでは使えません」と表示され、サイト固有の操作（このサイトの設定・ボタンを教える・再実行）は無効になります。

### 詳細設定（options ページ）

popup の「詳細設定」、または `chrome://extensions` の拡張カードの詳細から開けます。設定は変更するとその場で保存されます（保存ボタンはありません。変更のたびに「保存しました」と小さく表示されます）。ブラウザの同期ストレージには 1 項目あたりの容量上限があるため、教えたボタンを多数登録した場合など、保存に失敗することがあります。その場合は「保存しました」の代わりにエラーが表示されます。

- **どこまで許可するか**: 初期設定と同じ設定（3 つ + 「すべて拒否」）を選び直せます。その下には Cookie の種類ごとに 1 行ずつ並び、「必要なもの」は常に許可（変更不可）、それ以外は個別に ON・OFF を切り替えられます。個別に変えると、上の設定は「カスタム」という扱いになります
- **断れなかったとき**: 断るボタンが見つからない場合に「同意画面を非表示にする（おすすめ）」か「そのまま表示しておく」かを選べます
- **サイトごとの設定**: これまでに登録したサイト別の設定を確認・削除できます（「個別に調整」しているサイトは許可している項目も並びます）
- **教えたボタン**: これまでに登録した「教えたボタン」の一覧を確認・削除できます
- **判定ルールの更新**: 同意画面を見分けるルールを週に 1 回自動で更新します。最終更新日時の確認と「今すぐ更新」ボタンによる手動更新ができます
- **その他**: タブへのバッジ表示、同意画面の出現を監視する秒数（1〜120 秒、既定 20 秒）、デバッグログ、初期設定ページをもう一度開く導線をまとめています
  - デバッグログを有効にすると、細かい経過が `console.debug` に、**どの段階で何をしたか**が `console.info` に 1 行ずつ出ます（`容器: DIV.cmm-cookie-banner__actions 文字数 26 ボタン 2 件 [設定 / 全てに同意] cookieSpecific=true score=7 [attr-cookie/decision-strong/attr-banner/text-banner]` / `ヒューリスティック: 候補 0` / `設定パネル: 「設定の保存」を押した → 成功` / `パス: custom 0ms / com 3ms / quick 1ms / heuristic 6665ms 合計 6669ms → panel` など）。処理できなかったときは従来どおり最後に要約が 1 行出ます。うまくいかないサイトを報告するときは、この `[cookie-autopilot]` の行をまとめてコピーしてください
- **バックアップ**: 設定一式（基本設定・サイトごとの設定・教えたボタン）を JSON ファイル（`cookie-autopilot-config.json`）として書き出し・読み込みできます。**インポートはファイルに含まれる項目（サイトごとの設定・教えたボタン）を追加ではなく全置換します**（インポート前の内容は失われます）。件数の上限（サイトごとの設定 1000 件・教えたボタン 500 件）や値の形式（host は 253 文字以内、セレクタ・文言は 500 文字以内、サイトごとの設定は項目ごとの許可か「動かさない」、教えたボタンの動作は「断る」か「許可」のみ）を満たさないファイルは一切取り込まれず、エラーとして扱われます

## 仕組み

content script は各ページの `document_start` で起動し、まず `<style>` を注入して主要 CMP の容器やこれから検出する容器を `opacity:0; pointer-events:none` にします（**cloak**。`display:none` は使いません。可視判定やクリックを壊さないためです）。そのうえで次の層を順番に試し、いずれかが成功した時点で打ち切ります。

1. **カスタムルール**（教えたボタン）: 「ボタンを教える」で登録した安定セレクタ（無理なら正規化した文言）を探してクリックします
2. **即決 CMP 表**（`src/engine/cmpQuick.ts`）: OneTrust・Cookiebot・Didomi・Usercentrics など主要 CMP の容器・拒否・許可セレクタをあらかじめ収録した表です。該当すれば即座にクリックします。英語圏・グローバルで多い CMP（Insites cookieconsent・CookieFirst・Cookie Script・Cookie Law Info・Civic Cookie Control・Cookie Information・Piwik PRO・Shopify・Amazon・eBay・LinkedIn・adidas (Glass)・Yahoo・Evidon・Finsweet・Squarespace）も収録しています。ボタンを探すのは**その CMP の容器の中だけ**で、ページ全体には広げません（`#deny` ・ `#acceptButton` ・ `button[action-type="DENY"]` のような汎用的なセレクタが無関係な要素に当たるためです）。容器の中に見つからなければこの層は失敗として次に進みます。容器セレクタも、そのまま cloak（`opacity:0` の注入スタイル）に使われる以上「その CMP だと言い切れる」ものだけにしています
3. **Consent-O-Matic ルール**（`src/engine/com/`）: [Consent-O-Matic](https://github.com/cavi-au/Consent-O-Matic)（MIT）が公開しているルール集を流用し、独自の簡易インタプリタで解釈・実行します。対応している matcher は `css` / `checkbox` / `onoff` / `url`、action は `click` `multiclick` `list` `consent` `ifcss` `waitcss` `foreach` `hide` `wait` `ifallowall` `ifallownone` `runmethod` `runrooted`（`slide` `close` は no-op）です。カテゴリ単位の同意トグル（consent アクション）にも対応しています。ただし `hide` アクションが `html` ・ `body` やページ本体（`main` ・ `nav` ・ `article` を含む要素）を対象にしている場合は無視します（ルールの中には「まずページごと隠してから CMP を操作する」ものがあり、そのまま従うとルールが空振りしたときにページが数十秒まるごと白紙になるためです）。ルールが失敗したときは、そのルールが隠した要素をすぐ元に戻します
4. **文言ヒューリスティック**（`src/engine/detect.ts` ・ `src/engine/candidates.ts` ・ `src/shared/phrases.ts`）: 上記に無い独自実装のバナー向けです。位置（fixed/sticky）・role・id/class・aria-label・可視テキストからバナー容器を検出し、ボタンの文言を正規化したうえで「拒否語」「許可語」「禁止語」「非決定語（設定・詳細など決定ボタンとして扱わない語）」で採点し、最も確からしいボタンをクリックします。語彙は日本語と英語の両方を収録しています
5. **設定パネル**（`src/engine/panel.ts`）: 「設定」と「全てに同意」しか置かれておらず、断るボタンがそもそも無いバナー向けです。断るボタンが見つからないまま猶予（1 秒）が過ぎたときだけ、1 ページに 1 回だけ「設定」を押してパネルを開き、行の文言から用途（設定の記憶・アクセス解析・端末への保存・おすすめの表示・追跡型の広告）を読み取って、あなたの設定で許可していない項目のチェックを外し、「選択を保存」を押します。パネルに「全て拒否」があるときは、トグルには触らずそちらを押します。「必須（常に有効）」の行と、無効・読み取り専用のトグルは触りません。用途を読み取れなかった行は許可しません。パネルが「カテゴリのチェックの下に個別サービスのチェックが並ぶ」入れ子になっているときは、**カテゴリ側だけ**を操作します（カテゴリを外せば配下も一緒に外れるためです）。先頭にある「すべて選択する」のような一括のチェックは、押すと全部オンになることがあるので**どのモードでも触りません**

文言の正規化では、空白・句読点に加えてアポストロフィ・引用符・ハイフン・`&` ・ `+` ・括弧・`?` ・ `…` ・矢印などの約物をすべて落とします。"Don’t accept" ・ "opt-out" ・ "Accept & Close" のような英語ボタンの表記ゆれを、語彙側で 1 つずつ書き分けずに済ませるためです。

**`role` も `button` タグも持たないボタン**（`<div class="cc-btn">Got it!</div>` のような独自バナー）は、`onclick` 属性やボタンらしいクラス名からも候補にします。ただしこの追加ルールは**バナー容器の中だけ**に適用します。ページ全体に広げると、記事内のリンクやサイトのナビゲーションまで「ボタン」とみなしてしまうためです。判定（可視性・禁止語・非決定語・文言）はふつうのボタンとまったく同じ経路を通ります。

クラス名は部分一致ではなく**トークンで**照合します（クラス名そのものが `btn` ・ `button`、または `-btn` ・ `__button` のように区切り記号のあとで終わるもの）。`<div class="cookie-banner__buttons">` ・ `<div class="btn-group">` のような**ボタンの親ラッパー**を候補にしないためです。同じ理由で、この追加ルールで拾った要素は**内側に別のボタンを含んでいれば候補から外します**。ラッパーは中のボタンより先に見つかるうえ、文言が子ボタンの連結（"Accept all" ＋ "Reject all" ＋ "Cookie settings"）になって決定ボタンに化け、押しても何も起きないまま候補の枠を使い切ってしまうからです。また `<a href="/leave"><div class="btn">Decline</div></a>` のように**実ページへのリンクの中にある要素も、原則として候補にしません**（クリックがリンク側に伝わってページが遷移するためです）。

ただし、決定ボタンを `<a href="/consent/all">全てに同意</a>` のように**リンクで作っている同意画面**があります。これを一律に除いてしまうと候補が 1 つも集まらず、断ることも「断れなかったとき」の非表示もできないまま終わってしまいます。そこで、①バナーのテキストに Cookie 固有語（`cookie` / クッキー / `GDPR`）があり、②文言が**はっきりした決定語**（「全て拒否」「必要なもののみ」・"Reject all" ・ "Necessary only" などの拒否語／「すべて許可」・ "Accept all" のように総量を明示した許可語）で、③「絶対に押さない語」を含まない——この 3 つをすべて満たすリンクだけは候補にします。「プライバシーポリシー」「インプリント」「詳細」「OK」「No thanks」のような情報リンク・短い汎用文言は対象外です。断るリンクがあるサイトでは断れるようになり、「全てに同意」しか無いサイトでも（それを押さずに残すことで）同意画面を非表示にできるようになります。なお**「設定」ボタンだけはリンクを使いません**。押しても設定パネルではなく別ページが開いてしまい、以降の手順が空振りするためです。

バナー容器は `position: fixed` / `sticky` でなくても検出します。`id="cookie-banner"` のように id / class / aria-label が Cookie 系を名指ししていれば、ページ最上部にふつうに置かれた（`position: static` な）バーでも容器として扱います。

禁止語は 2 段構えです。

- **絶対に押さない語**（購入・決済・注文・削除・ログイン・登録・退会・解約・振込・寄付・送信など）は、自動処理でも「教えたボタン」でも押しません。「ボタンを教える」でこれらのボタンを選ぶこと自体を断ります
- **自動処理でだけ避ける語**（保存・Save・Apply・申込・予約・投稿・公開・解除など）は、Cookie 設定画面の「保存して閉じる」「Save and exit」のような正当なボタンにも当たるため、ユーザーが明示的に教えたボタンには適用しません
- 「確定」（「選択を確定」など）は禁止語ではなく非決定語です。自動では押しませんが、教えたボタンとしては使えます（「注文を確定」は「注文」が絶対に押さない語なので引き続き押しません）

容器そのものを見送る判定（危険文脈語。決済・削除・認証のダイアログをバナーと取り違えないための保険）は、**容器のテキストに Cookie 固有語（`cookie` / クッキー / `GDPR`）が無いときだけ**適用します。Cookie を明示している容器は Cookie バナーとみなし、上記のボタン単位の禁止語で守ります（英語バナー定番の "We use cookies **in order to** …" を取りこぼさないためです）

さらに、**id / class / aria-label に Cookie 系の手がかりが無い容器**は、テキストに Cookie 固有語が無ければバナーとして扱いません。手がかりは 2 段に分けています。

- **強い手がかり**（`cookie` ・ クッキー ・ `gdpr` ・ 主要 CMP 固有の id）: これだけでバナーの容器とみなします。その要素自身だけでなく、**5 階層以内の親**が持っている場合も同じ扱いです（`<div class="cookie-banner__actions">［設定］［全てに同意］［プライバシーポリシー］</div>` のように**ボタン行だけが最小の容器になる**構造では、その行のテキストに Cookie の語が無く、class だけが手がかりになるためです）。テキストが長い容器は見送りますが、この強い手がかりがある容器だけは上限を大きく取ります（設定パネルを開くと、本文に全カテゴリの説明と数十件のサービス名が加わって数千文字になるためです）
- **汎用の手がかり**（`consent` ・ `privacy`）: `class="consent-modal"` ・ `class="privacy-modal"` のような規約更新モーダルにも使われるため、`position: fixed` や `role="dialog"` と同じ扱いにし、テキストに Cookie 固有語があるときだけバナーとみなします

「利用規約を更新しました。新しい規約に同意しますか？［同意する］［同意しない］」のような規約更新モーダルを、許可モードで「同意する」・拒否モードで「同意しない」（英語なら "Decline"）と押してしまうのを防ぐためです。拒否語は容器の文脈に関係なく押せる設計なので、この容器の採用条件が拒否側の唯一の砦になります。同じ理由で「同意する」「Accept」のような対象を限定しない許可語も Cookie 固有語のある容器でだけ押し、容器の文脈なしで押すのは「すべて許可」「Accept all」のように総量を明示した言い回しに限ります

**年齢確認や医療従事者向けのゲート**（「Are you over 18?［Yes］［No］」の下に小さく "This site uses cookies…" と書かれているもの）は、Cookie の語があるためバナーの容器として検出されてしまいます。そこで容器のテキストに年齢・法定年齢・医療従事者を示す語（`18` ・ `21` ・ `age` ・ `of legal` ・ `healthcare professional` ・ 年齢 ・ 歳以上 ・ 未成年）があるときは、`OK` ・ `Continue` ・ `No thanks` のような**短い汎用文言を一切押しません**。拒否モードで「No」を押すとサイトから追い出され、許可モードで「Yes」を押すのは法的な自己申告の代行になるためです（`Yes` ・ `No` 単独はそもそも語彙から外しています）。`age` は "manage" ・ "storage" ・ "message" に部分一致しないよう単語として照合します。また、id / class / aria-label が入口ゲート・年齢ゲートを名乗る要素（`age-gate` ・ `age-verification` ・ `date-of-birth` 等）は、可視テキストの語とは別に、そもそも同意画面として検出しません（LEGO.com の「LEGO.comに入ります［続ける］／プレイゾーン」のような、Cookie の説明文が添えてあるだけの入口選択ダイアログを同意画面と取り違えないためです）。

**拒否側の取り違え**も防いでいます。`<button>Accept all<small>You can opt out at any time</small></button>` のように補足文が入った許可ボタンは、文言をつなげると "opt out"（拒否語）を含むため拒否ボタンに見えてしまいます。そこで「すべて許可」系の言い回しを含みながら否定形（`do not` ・ `don't` ・ `without` ・ `never`）を含まないボタンは、拒否モードの候補から外します（"Do not accept all" は否定形があるので従来どおり拒否ボタンです）。

許可するカテゴリ（「どこまで許可するか」の設定）が 1 つでも有効なときは、その設定を反映させるため 2 と 3 の順序を入れ替え、Consent-O-Matic ルールを即決 CMP 表より先に試します（既定の「最低限」は「設定の記憶」を許可するので、既定でもこの順序です）。

Consent-O-Matic ルールのうち、実際に実行できる手順（同意画面を隠す・設定を開く・カテゴリを選ぶ・保存する）を 1 つも持たないものは、検出した時点でスキップします（実行しても必ず失敗し、成功判定の待ち時間を捨てるだけになるためです）。

**断るボタンが見つからなかったとき**は、詳細設定の「断れなかったとき」の設定に従います。

- 既定は **非表示**: バナーの容器を `display:none` で隠します。ボタンを探すのは最も内側の容器ですが、隠すのは**それを含む最も外側のバナー容器**です（`.cookie-consent > .cookie-consent__actions` のような構造でボタン行だけが消えて本文が残る、という状態を避けるため）。ただし外側へ広げるのは id / class にバナーの手がかりがある容器までで、`position: fixed` ・ `sticky` や `role="dialog"` であることだけが理由の外側要素（バナーを内包しているだけの sticky ヘッダーなど）までは広げません。モーダル型のバナーは背景（バックドロップ）も一緒に隠し、そのときは容器自身も隠したうえで、背景側に**バナー以外の要素が後から追加されたら背景の非表示だけ解除**します（`#modal-root` のようなポータル用の要素をサイトが使い回すケースを壊さないためです。解除するときは、隠す前にその要素が持っていた `display` の指定に戻します）
- バナーがスクロールをロックしていた場合は解除します。`style` 属性で直接ロックしている場合は記録しておいた元の値に戻し、`body.modal-open` のようなクラス付与でロックしている場合は `overflow: auto` をインラインで当てて解除します（この上書きは、サイト側がその要素の `class` / `style` を変更した時点で自動的に外します。サイトが自分のモーダル用にロックし直すのを邪魔しないためです）。バナー表示前から `hidden` だったサイト本来の `overflow` 設定は原則そのままにしますが、**ページにスクロールすべき中身がある場合**（`scrollHeight` がウィンドウの高さを超える）は、最初からスクロールを止めている cookie wall とみなして同じように解除します
- **そのまま表示しておく**: cloak を解除して普通に表示します（何もしません）

クリックが効いたかどうかは、押したボタンとバナー容器の両方について「DOM から消えた／`display` ・ `visibility` で不可視になった／画面外に出た（`transform` で退場するバナー）／透明になった」で判定します。透明（`opacity: 0`）かどうかは**祖先も遡って**調べます（親要素をフェードさせて退場するバナーがあるためです）。`visibility` は CSS の継承で子まで伝わるので、その要素自身の計算値だけを見ます（親が `visibility: hidden` でもバナー側で `visible` に戻していれば、見えている＝退場していないと判定します）。この判定を誤ると「断ったのに失敗扱い」になり、消えたはずの同意画面に「断れなかったとき」の非表示まで掛けてしまうため、退場の見分け方は広めに取っています。

cloak は `document_start` から即座に効きますが、バナーの検出・操作（と MutationObserver による監視）は `DOMContentLoaded` 後に始まり、そこから `observeSeconds`（既定 20 秒）の間継続します。見つからないまま時間切れになれば cloak を解除して終了します。同じ要素へのクリックは 1 回まで、同じ Consent-O-Matic ルールを試すのも 1 ページにつき 1 回までです。一度処理が確定した後は同じページで自動的に再試行しないため、SPA などで後からバナーが出た場合は popup の「このページで再実行」を使ってください。

## 既知の限界

- **SPA 内のページ遷移では監視窓が再開しません**。監視は `DOMContentLoaded` 後からの一定時間（既定 20 秒）のみ行われ、`pushState` などによるクライアントサイド遷移で新しいバナーが出ても自動では拾いません。popup の「このページで再実行」で手動でやり直してください
- **`closed` な shadow DOM の中は操作できません**。`open` な shadow DOM は横断して探索・クリックできますが（`src/engine/deepQuery.ts`）、`closed` は仕様上たどれません。また **cloak（`opacity:0` の注入スタイル）は light DOM にしか効きません**。shadow DOM 内にバナー本体がある CMP では、探索・クリック自体はできても cloak では隠せず、処理が完了するまで一瞬見えることがあります
- **Consent-O-Matic の `slide` ・ `close` アクションは no-op です**（対応している matcher・action は「仕組み」の 3. を参照）。これらおよび未対応の action type・matcher type は、例外を投げずに無視して次に進みます（デバッグログのみ出力）
- iframe 内のバナー（Sourcepoint など）も `all_frames: true` によりフレームごとに独立して検出・処理します。どのフレームが処理したかはタブ単位で service worker が集約し（`handled` を優先）、popup の状態表示やバッジに反映しますが、フレーム同士が検出状況を直接やり取りすることはありません。**サブフレームからの「バナーはあったが処理できなかった（unhandled）」報告はバッジに反映しません**（`none` と誤認されないよう、トップフレームからの報告のみ反映します。`handled` はどのフレームからでも優先して反映されます）
- 文言ヒューリスティックは日本語・英語の語彙表に基づく判定です。それ以外の言語だけで書かれたバナーは検出できないことがあります（フランス語の "Tout refuser"、ドイツ語の "Alle ablehnen" などは即決 CMP 表や Consent-O-Matic ルールに当たらなければ処理できません）。英語は "Reject all" ・ "Decline optional cookies" ・ "Necessary cookies only" ・ "Continue without accepting" ・ "Do not consent" ・ "Disable non-essential cookies" のような**明示的な拒否**と、"Accept all cookies" ・ "Allow all" のような**明示的な許可**を中心に収録しています。"No thanks" ・ "Not now" ・ "Continue" のような**どちらにも取れる短い文言**は、容器のテキストに Cookie 固有語があるときだけ使います（ニュースレターの購読モーダルや通知の許可ダイアログを誤って操作しないためです）。"Yes" ・ "No" 単独は年齢確認ゲートを押してしまうため、どちらの語彙にも入れていません。"Manage preferences" ・ "Show purposes" ・ "Vendors" ・ "Confirm my choices" ・ "Do Not Sell or Share My Personal Information" のような**設定画面を開く／部分的に許可するボタンは決定ボタンとして扱わず**、自動ではクリックしません（ただし "Accept all purposes" ・ "Reject all vendors" のように「すべて」と総量を明示した決定語を伴う場合だけは、設定系の語を含んでいても決定ボタンとして扱います。"Manage or reject cookies" のように総量の明示が無いものは、拒否語を含んでいても設定ボタンのままです）。選択肢が 1 つだけの通知バナーを「閉じる語」（"Got it!" ・ "Continue" など）で閉じる動作は、**拒否モードでは設定ボタン**（"Manage settings" ・ "Preferences" など）**が同じバナーに残っているときは行いません**（その "Continue" は同意ボタンなので、代わりに「断れなかったとき」の設定に従います）。設定で「すべて拒否」を選んでいる場合も、この閉じる動作は行わず「断れなかったとき」の設定（既定は非表示）に従います。バナーを非表示にする判定（hide）は、Cookie 固有語（`cookie` / クッキー / `GDPR`）を含み、かつクリックしなかった許可ボタンが存在する場合に限定しています。弱い許可語（`OK` ・ `はい` ・ `同意` など）や閉じる語も、容器のテキストに Cookie 固有語が含まれるときだけ判定に使い、無関係な通知バナーを誤って閉じないようにしています
- **決定ボタンがリンク（`<a href="…">`）で作られている同意画面では、クリックでページが遷移することがあります**。サイトによっては「全て拒否」「全てに同意」が実ページへのリンクで、押すと同意を記録する URL へ移動する作りになっています。上記の条件（Cookie のバナーであること・はっきりした決定語であること・絶対に押さない語を含まないこと）を満たすリンクだけを押しますが、**押した結果としてページが切り替わる可能性は残ります**。「プライバシーポリシー」「インプリント」のような情報リンクは押しません
- **設定パネルを開く処理には、「設定」ボタンを 1 回押す動作が伴います**（拒否モードで、断るボタンが無い Cookie の同意画面に限ります）。パネルが出てこなかった場合や、パネルに入力欄・危険な文脈の語（削除・支払いなど）・保存に使えるボタンが無い場合は、**トグルに一切触れずに中止**して「断れなかったとき」の設定（既定は非表示）に従います。ただし「設定を送信」のように送信という語で選択を確定させる保存ボタンは、それ自体を危険な文脈語として中止の理由にはしません。ラジオボタン（「許可する／許可しない」の組）で選ばせるパネルは、どちらが拒否かを文言だけでは決められないため対象外です
- 「ボタンを教える」のセレクタ生成は、id・`data-testid` 等の安定属性・クラス名から一意なものを探しますが、見つからない場合はボタンの文言だけで運用されます。文言が変わるサイトでは効かなくなることがあります。教えたボタンはセレクタが一致しても即クリックはせず、保存した文言との一致・可視性・「絶対に押さない語」の有無を確認してからクリックします。また **「ボタンを教える」は最上位フレームに対してのみ動作し、iframe 内（Sourcepoint など）に表示されるボタンは選択できません**

## Consent-O-Matic との併用について

同梱の Consent-O-Matic ルール（`public/rules/consent-o-matic.json`）は [Consent-O-Matic](https://github.com/cavi-au/Consent-O-Matic) を出典としています。ライセンスは MIT で、全文を [`third_party/consent-o-matic/LICENSE`](third_party/consent-o-matic/LICENSE) に同梱しています。

**Consent-O-Matic 拡張本体を同時にインストール・有効化していると、同じバナーに対して両方の拡張が操作を試みて二重に動作します。** 本拡張を使う場合は、Consent-O-Matic 拡張は無効化することをおすすめします。

## プライバシー

利用者のデータを外部に送信することはありません。個人情報・閲覧履歴・ページの内容が開発者や第三者に渡ることはなく、拡張の設定は `chrome.storage` にのみ保存されます。詳しくは [PRIVACY.md](PRIVACY.md) を参照してください。

## 開発コマンド

| コマンド | 内容 |
| --- | --- |
| `pnpm install` | 依存関係のインストール |
| `pnpm build` | `dist/` に本番ビルド（`public/` の内容もコピーされます） |
| `pnpm package` | `dist/` の中身を `release/cookie-autopilot-v<version>.zip` にまとめます（実行前に `pnpm build` が必要） |
| `pnpm dev` | esbuild の監視ビルド（保存のたびに再ビルド） |
| `pnpm typecheck` | `tsc --noEmit` による型チェック |
| `pnpm test` | Vitest（jsdom）によるユニットテスト |
| `pnpm rules:fetch` | Consent-O-Matic のルールを GitHub から取得し直し、`public/rules/consent-o-matic.json` と `third_party/consent-o-matic/LICENSE` を更新します（初回ビルド前に一度実行しておきます） |
| `pnpm icons` | 仮アイコンを再生成 |
| `pnpm fixtures` | `dist/` と `fixtures/` を配信するローカルサーバ（`http://localhost:4173/`）を起動します。拡張として読み込まなくても、`fixtures/*.html` で content script の動作を、`popup.html` / `options.html` で見た目を確認できます（`chrome` API が無いため操作は無効化されます） |
